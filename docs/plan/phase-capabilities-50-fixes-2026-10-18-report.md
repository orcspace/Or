## Что ещё не работает / известные ограничения

- Отдельные MCP-команды одного вызова для специальной вставки и повестки отсутствуют: [mcp-gaps](../mcp-gaps.md). UI работает через существующие операции; это не закрывает полный UI↔MCP паритет.
- Паспорт читает сохранённые значения и прямые/именованные зависимости, не численный trace и не flush draft. Линза оформления ограничена body-абзацами со встроенными стилями.
- Повестка статична после создания, текст ограничен явно указанными пределами. Специальная вставка использует внутренний снимок; внешний системный буфер остаётся TSV.
- HTML-экспорт ограничен 32 МиБ и PNG/JPEG. Rich tables и merges сохраняются в HTML-выводе; существующий HTML-import по-прежнему упрощает таблицы и сложный CSS. Поддержаны data URI, сетевые изображения не загружаются.
- Markdown использует невидимый v2-комментарий для собственного точного round-trip пустых абзацев; legacy import сохраняет прежнюю обработку физических строк. Импорт произвольных GFM-таблиц остаётся упрощённым.
- Лимит 64 МиБ исходного текста Sheets и агрегатный лимит изображений могут отклонить ранее принимавшиеся чрезмерные/некорректные книги. Это не доказательство ограничения всей памяти вычислений.
- XLSX наследует стили строк/колонок для материализованных ячеек; полная модель стилей пустых областей не добавлена. PPTX поддерживает указанные четыре цветовых преобразования, не все DrawingML effects.
- Корректность вычислений с предельными f64, реальная точность Office round-trip, производительность, UI/Narrator и release-критерии SPEC-AUDIT остаются непроверенными.

Следующий шаг после снятия запрета владельцем: форматирование/компиляция, целевые регрессии, затем Windows UI/MCP/Office round-trip по docs/testing/acceptance.md. Полный паритет Office, release-ready и критерии SPEC-AUDIT не объявляются выполненными.
