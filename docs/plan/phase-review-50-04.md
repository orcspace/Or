# Пакет 04 — ИИ для нескольких редакторов одновременно

Основа — `0fb6408` / PR #6. Ветка `codex/review-50-ui-04`; отдельный PR поверх `codex/review-50-ui-03`.

Новое указание владельца 2026-10-15: улучшить инструменты ИИ, чтобы он одновременно работал с открытыми Docs/Sheets/Slides (Word+PowerPoint, Excel+Word и другие сочетания); самостоятельно продумывать фичи, сверять интернет в каждом обновлении. Сборка только по отдельной будущей команде. Общая работа продолжается до «стоп».

## Результат

1. Явный контекст открытых документов: ID, тип, версия, доступность правки. Ассистент выбирает документы по задаче пользователя, не привязывает все команды к активной вкладке.
2. Пакет операций по нескольким существующим документам через MCP. Каждый документ имеет исходную base_version; несовпадающие версии/права/ошибка любой операции не оставляют частично применённый пакет.
3. Подготовка моделей в фоне; независимые задания на разные документы могут готовиться одновременно. Содержимое фиксируется в UI через ops. Переходы между вкладками для выполнения правок не нужны. Конкурирующие задачи одного документа получают понятный busy/conflict.
4. Явные job ID, состояние, результат и отмена. Отмена/отзыв доступа/закрытие документа до commit запрещают применение. Успешный пакет создаёт по одной авторской undo-группе на изменённый документ и показывает затронутые документы в интерфейсе. Синхронный междокументный commit в UI не объявляется многопоточной записью модели.
5. Схемы и описания новых инструментов задают точные параметры/лимиты/статусы. Поддерживаются apply/dry_run; preview не меняет модель. Неподдержанные дисковые/внешние операции не прячутся в пакет.
6. Промпт встроенного чата учитывает многодокументную задачу и требует дожидаться результата задания, прежде чем сообщать успех. Внутренние операции существующих редакторов сохраняются.

## Проверка

Два независимых ревьюера продолжают аудит редакторов и расчётов; ориентир отдельного обновления — 50 различных подтверждённых причин, без счёта новых фич/повторов/собственных промежуточных ошибок. Регрессии на несколько документов, конфликт второй модели без изменения первой, отмену, отзыв доступа, независимые задания, сохранение пользовательского выбора и undo добавляются без запуска.

Только статические rustfmt/check-format, diff-check, spec/assets и чтение схем/первичных источников. Не выполнять build, cargo test/check/clippy, GUI, компилирующий CI, установщик или релиз. Все мутации с orell_flow; не сливать PR. Никакой новой runtime зависимости и смены стека.

## Первичные источники, проверенные 2026-10-15

- [MCP 2026-07-28: Tools](https://modelcontextprotocol.io/specification/2026-07-28/server/tools): input/output schemas, structured results, корректные tool errors и индикаторы вызовов.
- [MCP 2026-07-28 release](https://blog.modelcontextprotocol.io/posts/2026-07-28/): явный handle для состояния между вызовами; новая версия протокола сама по себе не гарантирует готовность клиента/SDK.
- [Microsoft: App icons](https://learn.microsoft.com/en-us/windows/apps/design/iconography/app-icons): простая метафора и малые размеры. Новая белая иконка подготовлена в пакете03.

Это план реализации, не заявление о готовых многодокументных инструментах. Ограничения ресурса и способы проверки фиксируются в итоговом отчёте; цель полного Office/MCP parity сохраняется.

## Возобновление16.10.2026

Независимое чтение выявило два дефекта: stop/clear не отменяет выданные jobs; внешний stateless MCP2026 получает новый session ID на каждый call и теряет approval/ownership. Исправить PR7 до нового пакета: поколение чата и запрет старых запросов; явный128-bit client_access handle с подтверждением в UI, привязкой к имени клиента, сроком8ч и лимитом128 записей. В документах/авторах/логах хранить только публичный ID разрешения, не сам handle. Bearer/Host/Origin проверки сохраняются. Handle передаётся только top-level аргументом tool, не внутри operations. Отключение MCP аннулирует handles. Это поправка текущей реализации, не новые пункты квоты.
