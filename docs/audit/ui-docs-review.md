# Docs UI review — 2026-10-13

По последнему запросу владельца Docs получил минимальную однострочную ленту со вкладками «Главная», «Вставка», «Макет», «Вид». На «Главной» видны стиль, шрифт, размер, Ж/К/Ч и четыре вида выравнивания. Зачёркивание, над-/подстрочный текст, цвета, маркер и образец форматирования доступны через «Формат»; списки и отступы — через «Ещё»; буфер обмена, поиск, заголовки и таблицы — через «Правка». Крупная галерея стилей удалена, все прежние стили остались в списке. Белая страница центрирована; горизонтальная прокрутка сохраняет команды при узком окне, вертикальная резервирует статистику и масштаб.

Создание таблицы открывает отдельный редактор; он также доступен на «Главная» и «Вид». В нём меняются тексты ячеек, заливка, цвет границ, размер и формат текста, выравнивание, ширина столбцов. Добавление и удаление последних строк/столбцов подписано явно. ID существующих ячеек и форматирование окружающего текста сохраняются. Окна редакторов наследуют запрет правки родительской вкладки.

Исправления ревью: форматирование выделения до начала следующего абзаца больше не затрагивает этот невыделенный абзац; добавление столбца к импортированной таблице с неодинаковыми длинами строк корректно дополняет недостающие ячейки; авто-ID виджетов заменены стабильным ID ячейки. Рисование, hit-test, выделение, курсор и IME используют один центрированный origin страницы. Exact TextEditDelta и reconciliation MCP/undo сохранены.

Добавлены regression tests для смещённого hit-test с Unicode, границы выделения абзацев и столбцов ragged import. Сборку, fmt, clippy, полный набор тестов и просмотр реальных окон запускает root централизованно после слияния редакторов; этот отчёт не заявляет их прохождение заранее.

Ограничения: таблицы редактируются в отдельном окне, а не непосредственно на бумаге; форматирование команды «Формат» действует на всю ячейку. Объединение/разделение ячеек, точное мышиное перетаскивание границ и режим двух страниц рядом не реализованы. Это не полный паритет Word.

Второй проход: Ctrl+F и Ctrl+H переводят фокус на поля поиска и замены со стабильными ID до обработки текстового ввода. Canvas больше не применяет хвост Text/Paste после передачи фокуса. Поля получают ввод уже в кадре горячей клавиши; при повторном открытии используется тот же ID. Группа «Буфер обмена» выполняет реальные native RequestPaste/RequestCopy/RequestCut; Ctrl+C/X/V и внутренний буфер форматирования сохранены. Добавлены регрессии для same-frame хоткеев, late event dispatch и rich-text copy/paste/cut. Прохождение тестов проверяет root.

Дополнительно «Заменить» активна только для выделенного найденного совпадения; прежнее выделение постороннего текста защищено проверкой range и regression test.

Rich clipboard перенесён в shared egui context между вкладками; форматирование применяется только при совпадении internal payload с текстом системного буфера. Вставка создаёт свежие ID. Regression test покрывает rich copy A→B, allocator floor и последующую вставку другого системного текста без наследования старого форматирования. События текста до Ctrl+F в том же кадре сохраняются в документе, после хоткея идут в query (отдельная regression).

Минимальная лента: вкладки «Вставка», «Макет» и «Вид» также сведены к одной строке. Размер вставляемой таблицы и настройки изображений находятся в меню; создание таблицы по-прежнему открывает её редактор. Отступ перед рабочим полем сокращён с 8 до 4 px. Совместно с уменьшением группы в chrome с 62 до 28 px это отдаёт больше высоты документу; ширины групп главной ленты уменьшены с 1140 до 865 px без межгрупповых промежутков. Декоративных bitmap-ресурсов и новых зависимостей нет.

Проверка кода после изменения: команды используют прежние Doc/EditorState операции; формат применяется к выделению или будущему вводу, ID поиска/ячейки и точные TextEditDelta сохранены. Native RequestPaste/RequestCopy/RequestCut перемещены в меню и возвращают фокус canvas. Алгоритмы ввода, IME, rich clipboard, hit-test и редактирования таблицы не менялись. git diff --check для editor.rs прошёл; cargo, clippy, fmt и реальные окна централизованно проверяет root, результатов этого запуска здесь ещё нет.

Независимое read-only ревью App/chrome: нейтральное рабочее поле, тонкие разделители, группа 28 px и лента без общей рамки соответствуют минимализму. Действия Home/activate/close перенесены после commit редактора, с flush перед переключением/закрытием. Найден и передан root существовавший дефект Ctrl+K: палитра открывается после editor, её поле не запрашивает фокус, поэтому ввод после хоткея может попасть в документ. Этот отчёт не объявляет его исправленным.

Дополнительное ревью нашло обход disabled UI в собственном обработчике Docs: canvas мог сохранять фокус до создания отключённого виджета и применять Text/Paste/Delete. Исправлено: проверка ui.is_enabled() стоит перед определением активного canvas/find и в handle_event. Добавлена headless-регрессия: исходный документ с выделением и явно сохранённым фокусом остаётся идентичным при каждом из трёх событий внутри add_enabled_ui(false). Выполнение регрессии проверяет root.

Финальное независимое ревью нашло сброс формата пустой ячейки после следующего кадра: Paragraph::normalize удалял её единственный пустой run и создавал формат по умолчанию. Исправлено сохранение первого пустого формата, если абзац остаётся пустым; непустые runs по-прежнему объединяются как раньше. Regression создаёт реальную таблицу, задаёт пустой ячейке Arial/18 pt/Ж/К/цвет/маркер, дважды нормализует Doc (следующие кадры), затем вставляет Unicode через вложенный Doc так же, как редактор ячейки. Проверяются сохранение формата, ID ячейки/абзаца и текст первого ввода. Общие tests/fmt/clippy выполняет root централизованно; этот агент не объявляет их прохождение заранее.

Следующий независимый проход нашёл потерю raw Text при внешнем переключении до editor: успешная MCP-правка неактивной B переводила active с A, async Opened/Reload заменял текущую вкладку, Saved→close мог удалить её до обработки последнего ввода. Worker events перенесены после editor и пользовательских команд. Opened и MCP create активируют документ через deferred в конце кадра; обычный успешный MCP-write существующей B сохраняет active A, а last_agent/AI history остаются на B. Явное пользовательское переключение в этом кадре имеет приоритет. Dry-run не активирует последнюю вкладку и не создаёт присутствие агента.

MCP close_document теперь хранит запрос до завершения UI-editor, затем заново проверяет deadline/base_version/наличие документа/файловую занятость, выполняет фактический close и только после этого отправляет reply. Новый ввод делает исходно чистую вкладку dirty: reply честно сообщает applied=false/needs_confirmation=true; stale base_version даёт conflict. Восстановление и создание через пользовательский UI остаются явными действиями после editor.

Добавлены headless regressions с настоящим UI-фокусом и bridge/worker queues: Text в A + MCP insert B; MCP create + prefix A; async Opened + prefix; Reload completion против нового prefix; Saved→close против нового prefix; MCP close чистой A + prefix (confirmation и повторная версия). Отдельная регрессия покрывает deferred busy-reconcile. Ограничение: при unknown Docs model/history и заполненной positional queue существующий busy fallback всё ещё показывает B после editor, чтобы reconciled state не блокировал следующие MCP вызовы; ввод A текущего кадра сохраняется. Полное off-tab reconciliation не заявляется. Tests/fmt/clippy централизованно запускает root.
