# PR7 — завершение независимого ревью16.10.2026

Два новых независимых агента перечитали PR7 после возобновления. Найдены и исправлены две причины текущей реализации; они не добавлены к50 исправлениям и не перенесены в квоту05.

1. Stop/clear чата завершал CLI, но подготовленные workspace jobs могли примениться позднее. Теперь поколение клиента меняется при явной остановке/очистке. Запоздавшие вызовы старого поколения отбрасываются перед approval и flush; jobs и отложенные closes повторно проверяются перед применением. История jobs остаётся читаемой текущему поколению того же встроенного чата. Уже применённые правки stop не откатывает.
2. rmcp3.5.0 создаёт Server через factory на каждый stateless запрос; прежняя авторизация/ownership по per-request session_id не работала между tools calls. Добавлен request_access:128-bit случайный client_access, подтверждение в UI, привязка к имени клиента, срок8ч и лимит128 записей. Последующие tool calls передают тот же client_access только top-level. В авторах/индикаторах/ключах approval хранится публичный «доступ N», секретный handle не сохраняется в документе. Запрет в UI, истечение и отключение MCP прекращают доступ.

Bearer/Host/Origin проверки сохраняются. Имя клиента не даёт права без случайного handle. Встроенный чат использует собственный nonce+поколение и не получает внешний handle. Nested handles в workspace operations запрещены. Отдельных зависимостей/изменений стека нет.

Регрессии добавлены для stop/clear, позднего запроса, смены transport session при том же handle, другого имени, отмены job, expiry/deny/revocation. **Не запускались**. Статическое независимое чтение обоих ревьюеров по обновлённым production app/chat/access/tools/server/workspace завершено без оставшихся подтверждённых блокеров. Новые тесты и финальная статика проверяются ведущим отдельно. Компиляция/runtime/GUI/производительность не доказаны.

Ограничения: это собственные tool-level handles, не протокольный Tasks extension. Stateless read_resource не передаёт client_access и остаётся GAP; внешнему клиенту использовать инструменты. Handles и jobs не переживают перезапуск приложения. Legacy per-session approval сохранён для stateful клиентов. При отзыве доступа job отменяется до commit; кооперативная подготовка может завершиться позже.

Первичные источники16.10.2026: [MCP Tools: stateful tools и schemas](https://modelcontextprotocol.io/specification/2026-07-28/server/tools); локальный rmcp3.5.0 transport/streamable_http_server/tower.rs, get_service/serve_directly_with_ct. Имплементация не выдаётся за полную MCP2026 совместимость.
