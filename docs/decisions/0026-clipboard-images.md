# ADR-0026 — Вставка картинок из буфера обмена через arboard
Дата: 2026-10-13. Статус: предложено (нужно подтверждение владельца).

## Контекст
egui 0.36.2 передаёт приложению только текстовую вставку (`Event::Paste(String)`). Если в буфере только картинка (скриншот, рисунок из Word, PowerPoint или браузера), Ctrl+V ничего не делает. Это расходится с Word и PowerPoint (ADR-0017).

## Решение
Прямая зависимость `arboard =3.6.1` с `default-features = false, features = ["image-data"]`. Тот же крейт той же версии уже входит в сборку через eframe/egui-winit и прошёл проверку лицензий (`docs/licenses.md`). В `Cargo.lock` изменилось только ребро `trinedocs → arboard`, новых крейтов нет. Небезопасный код в TrineDocs не нужен.

Модуль `clipboard.rs`: если Ctrl+V или Shift+Insert не принесли текст, оболочка читает картинку из буфера (до 8192×8192), кодирует её в PNG и на 2 с отдаёт активному редактору. Docs вставляет рисунок после абзаца с курсором, Slides — объектом-изображением, Sheets — плавающим рисунком у выделенной ячейки (сохраняется в xlsx как drawing). Кнопка «Вставить» на ленте сначала берёт текст, а если его нет — картинку.

## Последствия
HTML, RTF и форматы Office из ADR-0017 по-прежнему не разбираются.
