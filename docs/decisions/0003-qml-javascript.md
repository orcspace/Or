# ADR-0003: QML при полном запрете JavaScript

Статус: **ждёт владельца**. Дата проверки 2026-10-12 UTC.

Факт: [официальные QML property bindings](https://doc.qt.io/qt-6/qtqml-syntax-propertybinding.html) используют JavaScript expressions, включая простую ссылку на свойство. Даже `color: Theme.background` — такая привязка. `qsTr` и signal handlers также нужно согласовать с абсолютным запретом JS. Rust не устраняет JS-семантику QML-bindings.

| Вариант | Возможности | Ограничения/стоимость |
|---|---|---|
| Разрешить декларативные QML expressions и тонкие вызовы Rust; запретить JS/TS файлы и business logic | обычная Qt Quick архитектура, state/ops в Rust | исключение из жёсткого запрета, принимает владелец; труда меньше относительно остальных |
| Буквальный запрет JS, статический QML и native updates | нет написанного JS | ручное связывание каждого свойства/сигнала, qsTr/theme singleton требуют исследования; труд больше, ещё не измерен |
| Другая UI-технология | обход фундаментального конфликта | смена жёсткого Qt Quick/QML стека, не разрешена |

Рекомендация: первый вариант с формальным ограничением: только property relations и однострочные обращения в CXX-Qt; никаких алгоритмов/IO/model ops в JS. **Это предложение, не принятое исключение.**

Блокируется интерактивный QML/UI; независимый Rust core продолжать. Никакие QML JS handlers в текущий код не добавлены.
